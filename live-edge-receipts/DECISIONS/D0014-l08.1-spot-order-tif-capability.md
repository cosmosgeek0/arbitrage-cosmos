## Decision

Adopt one content-addressed `BINANCE_SPOT_ORDER_TIF_CAPABILITY_V1` value. L04
may construct it only by validating the accepted immutable registry snapshot,
checking the exact current documentary contract, and rerunning exact static
sizing for one Spot `LIMIT` request with `GTC`, `IOC` or `FOK`.

The value binds product/environment, L02 matrix and contract identities,
official source pins, symbol/base/quote/side, instrument/source/registry/
snapshot revisions, exact preflight revision, price, requested and filtered
quantity, result notional, injected time and exclusive validity. It is deeply
frozen and explicitly non-sendable.

The accepted L04 registry does not change. Its Spot TIF list remains empty and
its original loss codes remain intact. The bridge resolves only the exact
`SPOT_TIME_IN_FORCE_UNAVAILABLE` documentary/runtime join for its one request;
`SPOT_EXECUTION_RULES_UNAVAILABLE` and all other external requirements remain
visible. This is a narrow adapter, not new source truth.

L08 retains its original one-argument evaluator unchanged. A second explicit
owner-binding entry point accepts the current frozen L04 Runtime snapshot plus
the complete sizing/reference request and reruns the L04 binder internally on
every evaluation. It then validates the derived capability, exact leg
projection, capability-set dependency revision, evaluation interval and plan
evidence. This replay is the accepted waiting/current-owner seam: a receipt,
source-evidence, registry, snapshot, preflight, reference or documentary
change invalidates the prior leg/dependency rather than trusting a caller's
self-sealed projection. Without that envelope, Spot remains rejected exactly
as in accepted L08.

## Normal-Basis proof law

The only required positive proof has an exact Spot BUY leg first and exact
USD-M SELL leg second. Both are bounded LIMIT actions. The plan is `ORDERED`;
the second action's quantity source is `ACTUAL_FILL_OF_LEG` and references the
first Spot leg. Requested quantity and ACK remain non-fill evidence.

The output remains an advisory/synthetic plan value with no dispatcher,
coordinator, lifecycle, order request or canonical execution truth. Every
decision and plan stays `sendEligible=false`, `NONE_RECORD_ONLY`, and
`externalActionAuthorization=NONE`.
