machine-readable, hashable contract matrix and deterministic negative fixtures

## Source and truth laws

- Only official Binance developer pages are controlling evidence. Search-engine
  snippets, blogs, SDK behavior, code memory and archived third-party pages are
  not contract truth.
- Every fact names its product and realm. Spot, USD-M and Margin endpoints,
  streams, security types, limits and lifecycle rules cannot be substituted.
- Conflicting official Margin pages remain an explicit conflict/unknown until a
  controlling official page resolves them; never select the more convenient
  claim silently.
- A source record is dated evidence, not a permanent constant. Unknown or
  unverified fields remain `UNKNOWN`/`null`, never fabricated zeros/defaults.
- No source record grants private-read, signing, order, Margin, capital,
  execution or deployment authority.
- L02 performs no request to a private/signed endpoint and no socket/process
  lifecycle action. Deterministic tests are network-free.

## Required negative proofs

- The accepted current Spot private route fixture passes while an obsolete Spot
  private route fixture fails with a named reason.
- The accepted current USD-M route/transport fixture passes while a Spot or
  legacy/wrong USD-M route substituted into that product fails.
- Margin conflicts cannot be represented as verified/available truth.
- Cross-product host/path/security/lifecycle substitution fails closed.
- Unknown fields, duplicate IDs, duplicate semantic contracts, malformed URLs,
  missing source hashes/dates and inconsistent numeric bounds fail.
- Source modules import without network, filesystem, environment, timers,
  sockets, wall clock or runtime acquisition side effects.
