# L03 — signed kernel, clock and rate budgets

Status: `WORKING`

## Purpose

Build a deterministic, no-I/O signed-request kernel over the accepted L02
Binance documentary contracts. Deliver canonical serialization, product/key
signer abstraction, clock-offset estimation, deterministic request/client-order
identity, redaction, endpoint-specific rate/cooldown accounting and an
ambiguity state machine that makes automatic mutation resubmission
mechanically impossible.

This phase builds and tests construction/sequencing seams only. It does not
read credentials or accounts, make a public/private/signed request, open a
socket, send a test/live order, mutate Margin, deploy, restart or change
capital. Later external validation remains separately owner-authorized.

## Required implementation

### Canonical request construction

- Consume only a validated exact L02 `CURRENT` REST contract; never accept a
  free-form host/path/security tuple or silently switch product/environment.
- Canonically order and encode parameters without binary conversion of exact
  decimal strings. Reject duplicate/reserved fields, accessors, inherited
  values, unsafe text, non-finite/unsafe numbers, malformed percent encodings
  and size/count overflow.
- Support the exact reviewed Spot and USD-M signing encodings through a closed
  product/key-type abstraction. Cryptographic key material is supplied only to
  a narrow injected signer operation and is never retained, logged, reflected
  in errors or placed in a receipt.
- Keep canonical payload construction independently testable from signing.
- Build deterministic bounded request IDs and client-order IDs from explicit
  stable inputs and injected monotonic sequence; no wall clock, randomness,
  ambient singleton or import-time allocation.

### Clock estimator

- Use injected local send/receive monotonic times and official server time.
- Estimate offset from midpoint samples using a bounded median and explicit
  outlier/RTT rejection. Preserve unknown/unavailable/skewed state rather than
  fabricate zero offset.
- Produce a small bounded `recvWindow` decision only when evidence is fresh and
  within reviewed limits; otherwise block construction.
- Never schedule a sync or read wall clock inside pure domain code.

### Rate and cooldown budgets

- Consume exact L02 endpoint rate claims by product/contract ID.
- Track request weight, order count, known response-header observations,
  429/418 state, validated `Retry-After`, cooldown/circuit state and next safe
  request time from injected observations.
- Separate products, environments, scopes, intervals and endpoint conditions;
  no cross-casting or global fabricated budget.
- Read-only retry advice is bounded and explicitly idempotent. Mutations,
  test orders, cancels, borrow/repay and any ambiguous request never receive an
  automatic retry decision.

### Ambiguity and redaction

- Represent pre-send, not-sent, submitted, acknowledged, rejected, unknown,
  reconciliation-required and terminal-observed state losslessly, reusing
  canonical Foundation vocabulary/owners through narrow adapters where
  available.
- A timeout, connection loss or relevant 5xx after a mutation attempt persists
  `UNKNOWN`/reconciliation-required intent and blocks the deterministic client
  order ID from duplicate send. L03 may model this transition but creates no
  durable store and performs no reconciliation request.
- Error/result surfaces expose only bounded safe codes and redacted metadata.
  Credentials, signatures, signed payloads, listen keys, account values and raw
  URLs cannot escape through exceptions or logs.

## Deterministic tests

- Official public signing-vector payload/digest parity without real
  credentials or network access.
- Spot versus USD-M encoding/key-policy separation and wrong-product/realm/
  lifecycle rejection.
- Canonical parameter ordering, exact decimal preservation and hostile input
  failure cases.
- Clock median/outlier/RTT/freshness/skew/`recvWindow` exact boundaries.
- Endpoint-specific rate consumption, header reconciliation, 429/418 and
  `Retry-After` cooldown boundaries, clock regression and scope isolation.
- Mutation timeout/5xx/disconnect transitions to reconciliation-required and
  produces zero automatic resubmission advice.
- Deterministic ID collision/domain-separation/bound tests.
- Recursive redaction and no raw sensitive material in errors.
- Import purity and static no-network/no-env/no-fs/no-timer/no-random/
  no-authority proof.
