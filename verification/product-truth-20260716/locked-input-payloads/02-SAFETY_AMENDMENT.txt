## Can AI-Ops use your subscriptions instead of expensive API billing?

Yes—but through logged-in Codex/Claude Code workers, not by pretending your subscription is a generic model API.

* Codex supports ChatGPT subscription sign-in, and `codex exec` reuses saved CLI authentication. Therefore an event-triggered Codex worker on your trusted machine can consume your ChatGPT/Codex subscription limits rather than API credits. Formal unattended Codex access tokens are currently limited to Business and Enterprise; consumer accounts should use the logged-in CLI or desktop scheduled tasks. [OpenAI authentication](https://learn.chatgpt.com/docs/auth), [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [scheduled tasks](https://learn.chatgpt.com/docs/automations), [access tokens](https://learn.chatgpt.com/docs/enterprise/access-tokens).

* Claude Code supports Pro/Max subscription login. Anthropic also documents `claude setup-token`, which creates a one-year subscription OAuth token for scripts. It uses plan limits—not API billing—provided `ANTHROPIC_API_KEY` is absent and you decline API credits. [Claude authentication](https://code.claude.com/docs/en/iam), [Claude Pro/Max usage and billing](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan).

The correct runtime design is:

* deterministic watchdog always running;
* meaningful anomaly triggers a bounded Claude/Codex CLI job;
* LLM diagnoses and creates a patch in an isolated worktree;
* independent verification checks it;
* money-path, risk-policy, deployment and credential changes require your approval;
* no LLM sits inside trading latency or directly signs orders;
* dashboard shows its queue, authentication status, remaining limits, permissions, findings, patches and approvals.

So yes: the resident AI can use your subscriptions. It should be an out-of-process, event-triggered supervisor—not an API call on every market event and not one endless chat.
